# Production Operator Runbook

Local-first, review-gated faceless YouTube production system.

---

## Local setup

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # edit as needed
alembic upgrade head          # apply migrations
python -m app.seed            # optional: seed first channel
uvicorn app.main:app --reload
```

Open the dashboard at `http://127.0.0.1:8000/` or explore the API at `/docs`.

`ffmpeg` is required for local draft preview rendering and final production export rendering.

## Internal API key

When `APP_ENV=production`, every write request must include:

```
X-Internal-API-Key: <your key>
```

Set `INTERNAL_API_KEY=<your key>` in `.env`. The dashboard reads it from `localStorage` via the API Key field in the top bar.

In development mode (`APP_ENV=development`), the key is not required.

## Review gates

The system enforces several mandatory human review steps before any output can be used. **No gate can be bypassed in normal operation.**

| Gate | What it blocks |
|---|---|
| **Asset review** | Must approve generated script/assets before packaging |
| **Preview review** | Must manually confirm the draft preview before package |
| **Visual asset review** | All registered visual assets must be approved |
| **Final voiceover gate** | Production voiceover must be from an approved provider (OpenAI or ElevenLabs) |
| **Metadata gate** | Title/description must not contain placeholder text |
| **Final export gate** | Final export artifacts must exist before upload |

A video's `production_ready` field is `false` until every gate is satisfied.

## Draft preview vs. final export

### Draft preview (`out/previews/{video_id}/draft.mp4`)

- Created by `POST /videos/{video_id}/preview/render-draft`
- For local QA only — confirms script and timing
- Does **not** satisfy the final export requirement
- Can use macOS `say`, silent fallback, or cloud TTS

### Final export (`out/final_exports/video_{video_id}/final.mp4`)

- Created by `POST /videos/{video_id}/final-production/export`
- Only runs when voice, visuals, metadata, and ffmpeg readiness all pass
- Uses an ffmpeg slideshow pipeline with approved visuals + production final voiceover
- Creates artifacts:
  - `final.mp4` — local final render artifact
  - `final_export_manifest.json` — final export metadata and readiness trace
  - `render_plan.json` — render input plan and asset mapping
  - `render_command.json` — executed command trace
  - `slides_concat.txt` and segment files — local ffmpeg intermediates
- The manifest includes a clear note: *"This is a local export artifact. It has not been uploaded to YouTube."*
- If ffmpeg is missing or fails, export returns blocked with a clear blocker and does not leave a `final.mp4` behind

## Final voiceover requirements

Production voiceover must be generated by a cloud TTS provider. The system enforces this by reading `voiceover_meta.json` and rejecting draft providers.

**Accepted providers:** `openai`, `elevenlabs`

**Rejected providers (blockers):** `macos`, `silent`, `fallback`, `local`

Voiceover files go in: `out/final_voiceovers/video_{video_id}/voiceover.mp3`

Check readiness before generation:

`GET /videos/{video_id}/final-voiceover/readiness`

- Local-only check.
- No OpenAI/ElevenLabs API calls are made.
- Returns provider-level booleans only (for example `api_key_configured`) and never returns secret values.

Required environment variables for production voiceover generation:
- OpenAI: `OPENAI_API_KEY` (optional overrides: `OPENAI_TTS_MODEL`, `OPENAI_TTS_VOICE`)
- ElevenLabs: `ELEVENLABS_API_KEY`, `ELEVENLABS_VOICE_ID` (optional override: `ELEVENLABS_MODEL_ID`)

Preview request before generation:

`POST /videos/{video_id}/final-voiceover/dry-run`

- Dry-run only.
- No OpenAI/ElevenLabs API calls are made.
- Returns provider/model/voice, script counts, excerpt, estimated duration, and safe request preview fields.
- Does not create final voiceover files.
- Does not satisfy the final voiceover gate.

Generate via `POST /videos/{video_id}/final-voiceover/generate` — requires `OPENAI_API_KEY` or ElevenLabs credentials.

Operational note: production voiceover credential/setup work can be intentionally deferred during local renderer/dashboard phases. In that mode, final export stays blocked by design.
Local/Mac/silent preview voiceover is draft-only preview audio and is never accepted for final export.

## Visual generation workflow

1. **Create a visual asset plan** — `POST /visual-assets/from-video/{video_id}`
2. **Queue local generation jobs** — `POST /visual-generation/plans/{plan_id}/queue` with `{"provider": "local"}`
3. **Run local generation** — `POST /visual-generation/jobs/{job_id}/run-local`
   - Creates a deterministic placeholder PNG under `out/visual_assets/video_{video_id}/`
   - Registers a `VisualGeneratedAsset` row with `review_status=pending`
   - **Never auto-approves assets**
4. **Review each asset manually** — `POST /visual-generation/assets/{asset_id}/approve` or `/reject`
5. Final production blocks until all assets for the plan are approved

To replace placeholders with real generated images: use the `register-output` endpoint to point an existing job at a real file.

## Manual upload workflow

After `production_ready=true`:

1. Check the export manifest: `out/final_exports/video_{video_id}/final_export_manifest.json`
2. Review `render_plan.json` and `render_command.json` if you need render traceability
3. Review the publishing payload: the JSON file in `out/publishing_payloads/`
4. Open YouTube Studio
5. Upload manually using the metadata from the payload file
6. Call `POST /publish/{video_id}/mark-published` after upload completes

**No automated upload exists. This is intentional.**

## Dashboard workflow controls

The dashboard includes `Selected Video Workflow Controls` so operators can complete local workflow steps without curl:

1. Refresh selected video status
2. Approve all pending visual assets
3. Approve video
4. Render draft preview
5. Mark preview reviewed
6. Build package
7. Prepare YouTube payload
8. Generate publishing payload
9. Check final production
10. Run final export

The panel surfaces final-production blockers directly and does not bypass any gate.
It now also surfaces production voiceover readiness (OpenAI/ElevenLabs configured/not configured) without exposing secrets.
It now includes `Preview Final Voiceover Request` for dry-run request preview without spending API credits.

### One-command smoke test (no live server required)

```bash
python scripts/local_workflow_smoke.py
```

What it validates:
- Video + asset generation, visual placeholder registration, manual approval gates, preview/package/payload steps.
- Metadata blocker detection + cleanup.
- Final export refusal when production voiceover is missing.
- No automatic publish/upload behavior.

The script uses an isolated temporary SQLite DB and output root so it does not touch existing local operator data.

### Curl fallback commands

```bash
# approve pending visual assets (repeat per asset id)
curl -X POST http://127.0.0.1:8000/visual-generation/assets/{asset_id}/approve

# approve video
curl -X POST http://127.0.0.1:8000/videos/{video_id}/review \
  -H "Content-Type: application/json" \
  -d '{"passed":true,"reviewer":"operator","notes":"Manual workflow approval"}'

# render/review/package/payload/final checks
curl -X POST http://127.0.0.1:8000/videos/{video_id}/preview/render-draft
curl -X POST http://127.0.0.1:8000/videos/{video_id}/preview/review -H "Content-Type: application/json" -d '{"reviewed":true}'
curl -X POST http://127.0.0.1:8000/videos/{video_id}/package
curl -X POST http://127.0.0.1:8000/publish/{video_id}/prepare-youtube-payload
curl -X POST http://127.0.0.1:8000/videos/{video_id}/publishing-payload/generate
curl http://127.0.0.1:8000/videos/{video_id}/final-voiceover/readiness
curl -X POST http://127.0.0.1:8000/videos/{video_id}/final-voiceover/dry-run -H "Content-Type: application/json" -d '{"provider":"openai","max_chars":5000}'
curl http://127.0.0.1:8000/videos/{video_id}/final-production/status
curl -X POST http://127.0.0.1:8000/videos/{video_id}/final-production/export
```

## Safety boundary

This system **never** automatically uploads content to YouTube. The `ENABLE_YOUTUBE_UPLOADS` flag exists in the config but is enforced as `false` in all production gates. Connecting OAuth and enabling uploads requires deliberate code changes that should go through review.

No content leaves this machine without the operator manually using YouTube Studio.
